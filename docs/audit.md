# Audit du site (état de `master` au commit `209636c`)

- **Date** : 2026-11-14
- **Périmètre** : tout le code de `app/`, les templates, la configuration, les tests et la documentation de `master`. La branche `feature/production-ready` (non fusionnée) n'est pas auditée.
- **Méthode** : lecture du code, rejeu des parcours avec des tests fonctionnels temporaires sur la base de test (supprimés ensuite, non commités), comptage des requêtes avec le profiler, rendu des pages d'erreur dans l'environnement `prod` (serveur PHP temporaire), `composer check`, `doctrine:schema:validate`, `lint:twig`, `lint:container`.

## Résumé

1. L'ensemble est **cohérent et solide** : 426 tests passent (16 990 assertions), PHPStan niveau 8 sans erreur, schéma et migrations synchronisés, CI verte sur les trois dernières fusions.
2. Les points sensibles sont bien traités : verrous et transactions pour la commande, l'annulation, le paiement et la facture ; IDOR vérifié partout ; CSRF sur toutes les actions POST métier.
3. Les fonctionnalités développées séparément s'emboîtent bien : code promo + annulation + facture, réconciliation du panier + code promo, cache + écritures ont été rejoués sans défaut.
4. **Aucun constat bloquant** pour un projet local. **7 constats importants**, 17 mineurs.
5. Problème n° 1 (A-01) : le formulaire d'administration d'une variante **écrase le stock** avec la valeur affichée à l'ouverture. Reproduit : 12 en stock, 3 vendus pendant l'édition, le stock repasse à 12.
6. Problème n° 2 (A-02) : une commande non payée **réserve le stock et l'utilisation du code promo pour toujours**. Il n'existe aucune annulation automatique, et une commande de plus de 100 € ne peut jamais être payée (plafond du paiement simulé).
7. Problème n° 3 (A-03) : en production, les pages d'erreur (404, 403, 500) sont **la page par défaut de Symfony, en anglais**, sans le gabarit du site. Elles s'affichent aussi pour un jeton CSRF expiré ou une variante devenue indisponible.
8. Sécurité : pas de limitation des tentatives de connexion (A-04), pas de CSP ni d'en-têtes de sécurité (A-05), déconnexion en GET sans CSRF (A-08).
9. Fonctionnalités citées mais **absentes** : favoris, avis, mot de passe oublié, pages d'erreur personnalisées, annulation automatique (voir la section dédiée). La documentation ne prétend pas qu'elles existent.
10. La documentation est riche mais a pris du retard par endroits : ADR 0007 et 0002, format des références de commande, README presque vide (A-22, A-23).

## Soupçons non vérifiés

- **Écran de 375 px** : aucun navigateur n'est disponible dans l'environnement, rien n'a donc été affiché. D'après le CSS (flex-wrap partout, tableaux dans `.table-wrapper` avec défilement horizontal), la mise en page devrait tenir. Deux points restent à vérifier à l'œil : (1) pour un administrateur connecté, l'en-tête passe probablement sur trois lignes (6 liens, sans menu repliable) ; (2) le titre « Commande CMD-20261114-2CCCCE » en 32 px forme une suite sans coupure possible (les tirets sont suivis de chiffres) et pourrait déborder horizontalement.
- **CSRF « sans état »** : `csrf.yaml` rend sans état les jetons `submit` (tous les formulaires Symfony) et `authenticate`. Sans le contrôleur JavaScript `csrf_protection_controller.js` (absent), leur validation repose sur les en-têtes `Origin`/`Referer`. Un navigateur ou une extension qui les supprime pourrait faire échouer les formulaires. Non testé dans un vrai navigateur.
- **Annulation et `EntityManager` fermé** : si `placeOrder()` échoue dans sa transaction (stock ou code promo), Doctrine ferme l'`EntityManager`. Le contrôleur ne s'en sert plus ensuite, mais un futur traitement par lot (A-02) devra appeler `resetManager()`, comme le signale déjà l'ADR 0007.
- **Collision de référence de commande** : 3 octets aléatoires par jour, sans nouvel essai si la contrainte d'unicité échoue (une 500 serait alors affichée). La probabilité est négligeable au volume actuel.

## Ce qui est bien fait (à ne pas casser)

- **Transactions et verrous** : commande, annulation, utilisation du code promo, paiement et facture sont chacun dans une transaction avec `PESSIMISTIC_WRITE`. Le numéro de facture sans trou (`INSERT … ON DUPLICATE KEY UPDATE` dans la transaction) est un modèle du genre.
- **IDOR** : commandes, factures, jetons d'API et API « mes commandes » cherchent toujours avec le client connecté et répondent 404 (testé pour chaque ressource).
- **CSRF** : toutes les actions POST métier (panier, code promo, paiement, annulation, statuts admin, révocation de jeton, suppression de catégorie) vérifient leur jeton, et des tests le contrôlent.
- **Contrôle d'accès** : `#[IsGranted]` sur chaque contrôleur protégé, doublé du filet `access_control` sur `/admin` et `/api/v1/me`. Chaque route de `debug:router` a été vérifiée : rien n'est exposé par erreur.
- **Montants** : tout est en centimes `int` ; les prix, libellés, code promo et remise sont copiés dans la commande puis dans la facture ; le calcul de la TVA est testé, arrondi compris.
- **Réconciliation du panier** : variante désactivée, produit désactivé, code promo devenu inapplicable, ancien panier d'avant les variantes, tout est retiré avec un message clair. Rejoué : retirer un article fait tomber le sous-total sous le minimum, et le code est retiré avec son explication.
- **Code promo + annulation** : l'utilisation est rendue sous verrou (rejoué : 1, puis 0 après annulation).
- **Cache applicatif** : invalidation par un écouteur Doctrine avec une seconde passe après le `COMMIT`, documentée honnêtement (ADR 0019) ; le tableau de bord passe de 7 à 2 requêtes.
- **Performances** : aucune page N+1 hormis A-09. Catalogue en 5 requêtes, admin en 2 ou 3, API en 4.
- **API** : contrat JSON par objets de sortie (aucune entité sérialisée), erreurs `problem+json`, limite de requêtes, jetons stockés sous forme d'empreinte SHA-256, profiler coupé pour ne pas enregistrer le jeton.
- **Photos** : type lu dans le contenu, liste blanche, nom aléatoire, `basename()` à la suppression.
- **Accessibilité** : `aria-current`, textes `.visually-hidden` sur les boutons répétés, vrais `<button>` et `<label>`, choix de variante sans JavaScript.
- **Qualité** : 426 tests utiles (les rares tests sans `assert` vérifient des attentes de mock, ce qui est légitime), PHPStan niveau 8 sans baseline, PHP-CS-Fixer, CI complète (lint Twig/YAML/conteneur, schéma, `composer audit`).
- **Documentation** : 21 ADR qui exposent les alternatives et les limites connues. C'est rare et précieux ; il suffit de les tenir à jour (A-22).
